# AGENTS.md

Vanr is an open source workspace where people and AI agents work together: chat, wiki, databases, routines and connectors. Bun monorepo: apps in `apps/`, shared packages in `packages/`.

## Verification

Locally, before saying a change is done, run only the light checks: `bunx biome ci .`, `bun run typecheck`, and the tests of the files you touched (`bun test <file>` in the package that owns them). Don't run the full test suites, `bun run build` or the end-to-end journeys on your machine: CI runs all of them on every pull request and on every push to `main` (the root `bun test`, the `web` job with the web tests and build, and the `e2e` job), and their results are the gate. A branch with no open pull request gets no CI run, so open the pull request before you rely on it. When you need evidence from a journey, read the head's CI run and download the `e2e-playwright-attempt-N` artifact, which holds the Playwright trace and report. If a failure can't be explained from that artifact, run a single journey locally with `bun run e2e -g '<journey>'` inside `apps/web`, one at a time. The web's end-to-end journeys (Playwright, `bun run e2e` inside `apps/web`) boot the real server on an in-memory PGlite per worker and run in the `e2e` CI job; new journeys build on the fixtures in `apps/web/e2e/fixtures.ts`. CI (`.github/workflows/ci.yml`) also runs the UI gallery build (`bun run --cwd packages/ui gallery:build`), the runner's sandbox tests (they need bubblewrap and socat) and the Postgres-backed tests. Those skip unless `VANR_TEST_POSTGRES_URL` points to a throwaway Postgres with pgvector: the tests create databases on that server. The `postgres` job in `ci.yml` lists the files and the env flags of each run. A change under `.github/` must pass actionlint and zizmor, and gitleaks scans the commits of every PR and push for secrets; `ci.yml` pins the versions of all three.
